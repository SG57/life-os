# Shared departments — two people's installs, one department

A shared department joins the same catalog department across two (or more) people's separate Life OS installs — a couple's Couples department, a shared home purchase, a family caregiving effort. The assistants never message each other directly; a **shared record** is the only wire, exactly as one shared record wires the departments inside a single install (S11).

## Structure (per counterparty)
In a shared store both people can reach (Google Drive or equivalent):

```
Shared Departments/
  <Person Name>/                  ← one root per person; SHARE THIS level, never the parent
    START HERE — Bridge Home      (the map + read-first pointer)
    CHARTER                       (the bridge charter: neutral-mediator rules)
    Bridge Protocol               (how topics, decisions, and queries move)
    Discussion Log · Decisions Log · Accountability Query Log
    Topics/                       (one doc per open topic)
    <Department Name>/            ← one subfolder per shared department
      Shared Record — <Department Name>
```

Permissions follow people: everything a counterparty may see lives under their root and nowhere else, so a second bridge (a parent, a business partner) gets its own sealed root and can never inherit the first person's access.

## Rules
- A department is shared **only when both people have installed it as shared**. One side marking it shared shares nothing.
- Inside shared departments and the shared record, both assistants work under the charter: neutral mediator, Socratic, facts only. Outside the shared space, each assistant remains its own person's advocate — neutrality is scoped, never global.
- Only what is written in the shared record crosses. Neither assistant can see the other's install, memory, or other departments — by design, not by policy toggle.
- Accountability questions run by mutual consent, in the open: both sides see the query log (see `couples/CHARTER.md` for the reference charter).
- Either person can pause or end sharing at any time, no reason needed ("couples stop" / "stop sharing" in the kernel). Ending sharing closes the wire; the shared record remains as the history both people already saw.

## Setup sequence
1. One person creates the root, seeds the bridge documents and the department subfolders with their Shared Records.
2. The root is shared with the counterparty (Editor).
3. The counterparty's assistant reads START HERE → CHARTER → Bridge Protocol, and marks the agreed departments shared in its own install.
4. Both sides record, in their own profile, which departments are shared and where the shared record lives.

## When Life OS suggests sharing (the share check)
Shared departments should rarely be the person's idea to request — the system notices first, because noticing is the mental load it exists to carry (rule S13). The suggestion is a proposal, never an action: nothing is ever shared silently.

**Signals** that a department wants a second person:
- The department's subject materially involves another identifiable person — a partner in Us, a co-buyer in a home search, a parent in Caregiving, a travel companion in Trips.
- The person names a partner, fiancé(e), or spouse while working in a life area that has a joint shape — planning a wedding, hunting for a house together, raising a topic both people keep touching.
- A joint commitment actually starts: a shared purchase, a shared search, a shared plan with dates and money.

**The offer.** HQ makes it once, plainly, naming the concrete payoff rather than the machinery: "Want to make the home search shared with your partner? You'd plan it in one place — the same record, both of your assistants able to help, no forwarding each other screenshots." If the counterparty has no Life OS yet, the offer includes that path ("they'd get the most from it with their own install — setting that up takes one sitting"). A yes runs the setup sequence above. 

**Restraint (a suggestion that nags is load, not relief):**
- At most one suggestion per department per pair of people. A no is recorded and respected; it is re-asked only when the situation materially changes (an engagement, a move actually starting, a joint purchase going live).
- Suggestions route through HQ: a department that spots the signal flags it "for HQ: share check — <department> with <person>", and HQ makes the one offer in the main chat. Departments never pitch sharing themselves.
- Never suggested: anything the person has marked private or never-touch, and departments whose content is ordinarily one person's own (personal health detail, individual debts, private journaling) — unless the person raises sharing first. The share check keys on joint *activity*, not on the mere existence of a relationship.
