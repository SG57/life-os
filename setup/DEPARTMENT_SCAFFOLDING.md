# Department scaffolding

Department scaffolding is part of the kernel's setup script so that it travels inside the one setup message: BOOTSTRAP step B10 and rules D1 to D4 in `kernel/BOOTSTRAP.md` (also in `dist/PASTE-SETUP.txt`); after setup, departments run under RHYTHM R24 to R27, which stay loaded. Follow those. Department rules and intake questions come only from each department's AREA message (D2), never from a summary.

Earlier versions (3.1.0 to 3.5.3) kept these rules here as S1 to S13. Where each one went:
- S1 (scaffold the whole catalog) and S2 (one read-back, one yes): B10.
- S3 (seed each chat): D3. S4 (no chats: named sections): D1.
- S5 (HQ is the switchboard) and S11 (one shared record): RHYTHM R24.
- S6 (record the map) and S10 (waking): RHYTHM R26, with Oversight O3 for waking.
- S7 (existing chats): D4. S8 (intake one department at a time): RHYTHM R25. S9 (departments reach out through HQ): RHYTHM R26.
- S12 (stay current): SAFETY S5.1 and `setup/UPDATE_CHECK.md`. S13 (share check): RHYTHM R27.
